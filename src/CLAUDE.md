## 공통

- 경로는 반드시 `config.py` 의 `DATA_RAW` · `DATA_PROCESSED` 를 쓴다. 문자열로 다시 적지 않는다.
- `venv/bin/python` 으로 실행한다. 셸의 `python` 은 다른 인터프리터일 수 있다.
- 수정 후 `venv/bin/ruff check` · `ruff format` 을 돌린다.

## collect_flights.py — 되돌릴 수 없는 데이터

**API 는 D-3 까지만 준다. 나흘을 놓치면 그 날짜는 영구히 복구 불가다.**
이 파일을 고칠 때는 수집이 멈추는 실수가 가장 비싸다. 수집 경로를 건드렸으면
반드시 한 번 실행해 결과를 확인한다.

전처리에서 이미 처리 중인 API 함정들(README 에 근거 있음):

- **코드쉐어 중복** — `masterflightid` 는 코드쉐어 행에만 채워진다. 단독편은 전부 결측이라
  `flightid == masterflightid` 로 거르면 정상 항공편이 통째로 날아간다.
  조건은 **결측이거나 주편명인 행**이고, 그 뒤에도 `fid` 중복 제거가 더 필요하다.
- **미확정편** — `rmkKor == '도착'` 인 행만 쓴다. `사전결항` 은 예정시각이 그대로 들어와
  지연 0분으로 보인다.
- **필드명 불일치** — 도착은 `arrAirportCode`, 출발은 `arrvAirportCode`.
- `numOfRows` 는 최대 100(문서에 없음). 오류도 HTTP 200 으로 오므로
  본문의 `OpenAPI_ServiceResponse` 유무로 판별한다.

## collect_metar.py

- 요청 파라미터에 `tz=Asia/Seoul` 을 넘겨 **KST 로 받는다.** 이걸 빼면 병합이 9시간 어긋나는데,
  METAR 가 24시간 있어서 커버리지만 봐서는 안 드러난다.
- `precip_mm` 은 RKPK 가 보고하지 않아 **항상 0** 이다. 피처로 쓰지 않는다.
- 아카이브에 산발적 결측이 있다(전체 0.18%, 가끔 하루 5~10시간). **정상이므로 메우지 않는다.**
  재수집해도 채워지지 않는다 — 2026-09-07 새벽에서 확인했다.
- 지난 연도 파일은 건너뛰지만, **이듬해 1월 2일 전에 받은 파일(mtime 기준)은 연말분이 빠져 있어
  다시 받는다.** 판정이 mtime 이라 **연말 전에 받은 파일을 복사하면 완결로 오인된다** — 옮긴 파일이 의심되면 `--force`.

## train.py

- **시계열이므로 랜덤 분할 금지.** `split_by_time()` 을 쓴다.
- **표본이 다르면 MAE 를 직접 빼지 말 것.** 사전예측은 전체, 이륙후는 출발지연 보유분(30%)
  에서 학습된다. 비교하려면 `--dep-delay-only`.
- **MAE 만으로 결론내지 말 것.** 지연이 0 근처에 몰려 있어 상수 예측인 베이스라인도 MAE 를
  낮게 받는다(`--dep-delay-only` 부분집합에서는 이번 회차(7,265편)에 사전예측이 19.69 로 베이스라인 19.46 에
  조금 뒤진다 — 6,823편 회차에는 19.08 대 19.56 으로 거의 같았고, 6,513편 회차에는 16.06 대 18.15 로 앞섰고, 5,424편 회차에는 반대로 베이스라인이 9.15 대 10.23 으로 앞섰다. 전체 표본에서는
  15.16 대 17.90 으로 사전예측이 이긴다. **어느 표본·어느 회차인지 밝히지 않으면 정반대 결론이 된다**).
  그러나 그 부분집합에서 15분 이상 지연 138편 중 **적중률이 0%·21%** 다 — 베이스라인은 중앙값이 음수라 한 번도
  경고하지 않고, 사전예측도 다섯 편에 한 편만 잡는다(오경보율 59%). 6,043편 회차에는 사전예측이 경고를 아예
  내지 않았다. MAE 로 앞서도 쓸모는 작다. 적중률·오경보율을 함께 본다.
  근거: `notebooks/02_error_analysis.ipynb` §3 (7,265편 기준)
- `metrics.csv` 는 열이 늘어나면 header 없는 append 가 깨지므로 **읽어서 concat 후 재작성**한다.
  지표를 추가할 때 이 구조를 유지한다.
- **목표는 예측 성능이다 (2026-11-14 방향 전환).** 지도교수 지시로 "기상의 효과"가 아니라
  "쓸 수 있는 정보를 다 써서 잘 맞히기"로 바꿨다. 근거: 10,473편 시점에 기상을 빼도 MAE 가
  14.03 → 13.74 로 오히려 나았다 — 기상만으로는 예측이 되지 않는다. 기상 피처는 그대로 두되
  새 정보를 단계별로 쌓는다(사전예측 → 회전편후 `rot_delay` → 이륙후 `dep_delay`).
  `rot_delay` 를 넣자 MAE 14.03 → 13.38, 출발지 기상(`o_*`)까지 넣자 13.04 (전체 10,473편, 테스트 10-31~).
  단 주간 4폴드로 다시 재면 출발지 기상의 몫은 −0.08분뿐이다(단일 분할의 −0.33분은 대부분 그 주의 우연).
  정보별 기여는 `notebooks/05_prediction_stages.ipynb` §1 제거 실험을 인용한다.
  이어 MAE 목적함수 + 편명 이력(`fn_*`)으로 주간 4폴드 평균 14.04 → 12.28 (`--weekly`). **개선은 단일 분할이
  아니라 `--weekly` 로 판단한다** — 테스트 구간 하나에서만 좋아지는 변경은 착시일 수 있다.
  편명 이력은 반드시 그날 이전 운항분만 쓴다(shift). 당일 실적이 섞이면 정답 누설이다.
  공휴일 플래그는 시험했으나 두 테스트 구간(10-17~·10-31~)에 공휴일이 없어 효과를 잴 수 없어 넣지 않았다.
- **과적합 방지: 11-14 이후 수집분은 최종 검증용으로 남긴다.** 위 비교는 같은 테스트 구간을
  보면서 고른 것이라 부풀려졌을 수 있다. 피처를 더 넣을 때는 11-13 이전 자료로만 판단하고,
  최종 보고 수치는 11-14 이후 자료로 한 번만 잰다. 하이퍼파라미터는 만지지 않는다.
  학습곡선이 1,000편대 이후 평평하므로 표본의 양보다 **정보의 종류**가 병목이다.

  실패한 시도를 반복하지 말 것 — 혼잡도(±30분 도착편 수)와 직전 1시간 평균지연은
  지연과의 상관이 0.05·0.09 로 신호가 없고, 넣으면 MAE 가 12.70 → 12.85·13.60 으로
  나빠진다. 횡풍 추가(`3f92853`) 때와 같은 패턴이다.
  회전편 여유시간(짝편 실제 출발 → 도착 계획 간격, 계획 왕복시간)도 주간 4폴드에서 12.28 → 12.21~12.23,
  한 주는 오히려 나빠져 넣지 않았다(2026-11-14). 짝편 지연이 흡수되는지는 트리가 이미 `rot_delay`·시간대로 배운다.
  당일 같은 항공사·같은 출발지의 이미 도착한 편(계획도착 60분 전까지) 평균지연도 주간 4폴드 12.22 → 12.25·12.18 로
  잡음 수준이라 넣지 않았다(2026-11-17).
  반면 편명 최근 7회 이력(`fn_med7`·`fn_late7`)은 시드 3개·12폴드 중 11개에서 개선되어 넣었다(2026-11-17):
  회전편후 주간 4폴드 12.27 → 12.07, ±10분 0.59 → 0.61. 지연경고 적중·오경보는 0.48·0.57 → 0.46·0.56 으로 그대로다.
  7 은 처음 정한 값 하나만 시험했다 — 창 길이를 테스트 구간에 맞춰 고르지 않는다.

  > 1,297편 시점에 사전예측이 베이스라인을 처음 앞섰다(MAE 12.86 대 14.22, R2 0.17).
  > 527편 시점의 "사전예측이 베이스라인에 진다" 는 더 이상 맞지 않는다.

  **'편수' 가 두 가지 뜻으로 쓰인다. 섞지 말 것.**

  | 말 | 뜻 | 예 |
  |----|----|----|
  | 전체 표본 크기 | `dataset.parquet` 의 행 수. 실행 시점을 가리킨다 | "1,297편 시점에 처음 앞섰다" |
  | 학습셋 크기 | 학습곡선에서 테스트셋을 고정한 채 늘리는 학습 행 수 | "학습 300편에서 처음 역전" |

  같은 '역전' 이라도 앞은 **실행 이력**(그날 돌렸더니 이겼다), 뒤는 **학습곡선 위의 한 점**
  (테스트셋 하나에 고정하고 학습량만 늘렸더니 이 지점에서 넘어섰다)이다. 숫자가 300 대 1,297
  로 크게 어긋나 보이지만 모순이 아니다. 인용할 때 어느 쪽인지 밝힌다.
