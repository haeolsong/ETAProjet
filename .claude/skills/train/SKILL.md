# 모델 학습·평가 절차

> ⚠️ `src/train.py`는 아직 없다. 항공편 API 응답 스키마가 확정되어야
> 피처와 타겟을 정의할 수 있기 때문이다(`/collect` 스킬의 `--probe` 참고).
> 아래는 구현할 때 지켜야 할 규칙이다.

```bash
source venv/bin/activate
python src/train.py   # 구현 예정
```

## 반드시 지킬 규칙

### 1. 랜덤 분할 금지

시계열 데이터다. `train_test_split(shuffle=True)`를 쓰면 미래 정보가 학습셋에 섞여
성능이 부풀려진다. **시간 기준으로 자른다** — 예: 마지막 3주를 테스트셋.

### 2. 베이스라인을 반드시 함께 보고

지연 분포는 0분 근처에 몰려 있고 가끔 크게 터진다. 그래서 **"항상 학습셋 중앙값을
예측하는" 모델도 MAE 12~15분**이 나온다.

목표인 "MAE ≤ 15분"은 이 바보 모델로도 달성될 수 있다.
베이스라인 비교표가 없으면 성능 수치가 아무 의미를 갖지 못한다.

### 3. 세 모델을 같은 코드로 비교

차이는 피처 목록 한 줄뿐이다.

| 모델 | 피처 | 역할 |
|------|------|------|
| 베이스라인 | 없음 (중앙값 고정) | 기준선 |
| 사전 예측 | `FEATURES_PRE` — 기상·노선·시간대 | **메인 서사.** 출발 전에 알 수 있는 정보만 |
| 이륙 후 | `FEATURES_PRE + ['dep_delay']` | 성능 상한선 참고 |

`dep_delay`(출발지연)는 도착지연의 압도적 1위 예측 변수다. 넣으면 MAE가 크게 떨어지지만
"출발지연 보고 맞힌 것 아니냐"는 지적을 받는다. 그래서 **메인은 사전 예측**으로 두고
이륙 후 모델은 비교용으로만 쓴다.

### 4. 결론 형태

> 출발 전 MAE X분 → 출발지연 정보 추가 시 Y분. 즉 그 정보의 가치는 (X−Y)분.

이 구조면 모델 성능이 낮게 나와도 유효한 분석 결과가 된다.

## 보고 지표

- **MAE** (주지표) — 평균적으로 몇 분 틀렸나
- **RMSE** — 큰 오차에 벌점. MAE보다 훨씬 크면 가끔 크게 빗나가는 모델이다
- **R²** — 참고용. 선행연구상 출발 전 예측은 0.10~0.30 수준이 현실적이다

결과는 `data/processed/metrics.csv`에 누적 기록한다. 실험할 때마다 덮어쓰지 말 것.
